Library guide

Choose the library you need.

Start with graphics and compute, or a focused module. The sensing libraries can process caller-owned samples without opening a device or starting a service.

Graphics and compute

Use etalon for the native/browser graphics API, or choose a focused extension. Packages are consumed through Git; pin a tested full commit for release. 

[dependencies]
etalon = { git = "https://github.com/mediaprophet/etalon.git", tag = "v0.0.2" }
pollster = "1.0"

Request an adapter and device through the same Rust API on supported backends. For runnable graphics, compute and validation checks, test this browser. The capability guide covers Forge, semantic data, tensors, rendering and execution coordination.

Etalon's fork packages and upstream crates.io wgpu/Naga packages are distinct; their types are not automatically interchangeable. Select matching Etalon packages in a consuming project.

Browser WebGPU adapters

For a workload that fits WebGPU Compatibility limits, request that level explicitly from Rust. The standard adapter method requests Core. Inspect the adapter's limits and request only the features and resources the workload needs; a missing adapter is a failed GPU capability check, not a CPU fallback. 

let adapter = instance.request_webgpu_adapter(
    &etalon::RequestAdapterOptions::default(),
    etalon::FeatureLevel::Compatibility,
).await?;

The browser API is available with Etalon's webgpu feature on wasm32. BrowserRequestRejected preserves a browser rejection; NotFound means no matching adapter was returned. The device suite reports GPU qualification separately from portable CPU results.

2. Compute I/Q power

This complete example decodes one little-endian signed-i16 pair and returns its uncalibrated squared amplitude. No acquisition or physical-unit interpretation is implied. 

use etalon_sense::signal::{
    decode::ByteOrder,
    pipeline::i16_iq_power_into,
};

fn main() -> Result<(), etalon_sense::signal::SignalError> {
    let raw = [3_u8, 0, 4, 0];
    let mut decoded = [0.0_f32; 2];
    let mut power = [0.0_f64; 1];

    let count = i16_iq_power_into(
        &raw,
        ByteOrder::LittleEndian,
        1.0,
        &mut decoded,
        &mut power,
    )?;
    assert_eq!(count, 1);
    assert_eq!(power, [25.0]);
    Ok(())
}

Keep the input encoding, scale, clock domain, calibration references and physical units alongside processed values. A numeric power value is not automatically watts, dBm, identity evidence or a calibrated measurement.

Native GPU and vendor adapters

Graphics and compute consumers use the etalon package. Prepared compute owns a private native Vulkan execution lane with fixed resources. Ordinary GPU providers and native runtimes do not automatically satisfy a strict hot zero-allocation requirement.

Select features = ["gpu-vulkan"] on the sensing facade for the GPU sensing API, including its prepared I/Q power provider. Preparation binds an actual selected adapter to host policy checks. The provider remains ColdUnbounded pending qualification; the logical buffer budget does not cap driver or policy callback allocation.

The vendor adapter workspace contains explicit DSP/FastRPC, RTL-SDR and model-runtime integrations. These are separate dependencies with SDK, driver, native allocation and licensing requirements. A generic sdr feature does not install or select an RTL-SDR driver.

Using observations with QualiaDB

Pass the common observation envelope with the exact resolved payload and a host-defined semantic mapping. QualiaDB owns its database, inference, Sanctuary/guardianship permissions and evidence custody. Capture approval does not implicitly authorize later processing, storage or export. Generic applications can implement their own authorities without depending on QualiaDB.

Device indices, USB strings, radio identifiers and declared source IDs are evidence inputs, not authenticated entity identities. Unknown timestamps, quality and uncertainty remain unknown.
