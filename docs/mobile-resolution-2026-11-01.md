# Mobile WebGPU resolution: review disposition, 2026-11-01

This records the disposition of the supplied **Etalon Mobile WebGPU Resolution Guide** against the development tree based on `9b888fb1`. It separates source repairs from hardware qualification and future architecture work. It supplements [the existing architecture review](plans/next-wave-architecture-review-2026-10-30.md), rather than replacing its priorities or evidence.

**Qualification is pending.** Local WASM compilation and lint checks passed, alongside 37 Python tests and 51 focused native unit tests. The expanded browser catalog contains 20 cases, including 18 GPU cases. The first hosted candidate, `ffe6bcb69`, passed 17 and failed three: Chrome rejected an out-of-range top-k float literal, and the canvas/lease cases reported a destroyed device. That failed run remains recorded in [Actions](https://github.com/mediaprophet/etalon/actions/runs/41273157279); the corrected candidate must pass before publication. No physical Pixel 10 Pro XL, Tensor G5, PowerVR Android Vulkan, Android NPU execution, or mobile performance result is established by those local checks. Earlier 13-case browser results apply to their recorded revisions, not this expanded candidate. Browser application qualification is not WebGPU CTS coverage; see [conformance coverage](conformance-coverage.md).

### Native-driver evidence

[Flutter's Pixel 10 report](https://github.com/flutter/flutter/issues/194034) records a depth/stencil load/store experiment that moved the crash rather than establishing a general solution. Flutter's [driver classification source](https://api.flutter.dev/impeller/driver__info__vk_8cc_source.html) does contain an Android vendor/device-specific raw `driverVersion < 6794074` guard. Its interpretation as a DDK build number is qualified in that source. The gate is real external evidence, but is not an observed Etalon failure, a universal vendor-version encoding rule, or a browser-acquisition fix.

[ExecuTorch's direct-barrier change](https://github.com/pytorch/executorch/pull/22147) replaced a no-op dispatch synchronization approach. Etalon already records direct Vulkan barriers in [command handling](../etalon-hal/src/vulkan/command.rs). Etalon also already checks `LAZILY_ALLOCATED` memory support for transient attachments in [Vulkan allocation](../etalon-hal/src/vulkan/adapter.rs). A vendor label alone must not overwrite that capability evidence.

### Android discovery evidence and limits

Google's [Janeiro kernel snapshot](https://android.googlesource.com/kernel/google-modules/edgetpu/janeiro/+/refs/tags/android-16.0.0_r0.8%5E!/) distinguishes the `edgetpu_platform` platform-driver name from the `janeiro` device name; it creates the `edgetpu` class and an `edgetpu-soc` interface. Google's [GS101 device rules](https://android.googlesource.com/device/google/gs101/+/refs/heads/main/conf/ueventd.gs101.rc) document `/dev/abrolhos`; [GS201 rules](https://android.googlesource.com/device/google/gs201/+/b0b2a4f90df3471bd4473fe0de88ab46621cb185/conf/ueventd.gs201.rc) document `/dev/janeiro`. These are verified interface families, not evidence that Tensor G5 uses a particular older chip name.

The shared driver classifier recognizes documented [QAIC](https://github.com/torvalds/linux/blob/master/drivers/accel/qaic/qaic_drv.c), [Ethos-U](https://github.com/torvalds/linux/blob/master/drivers/accel/ethosu/ethosu_drv.c), and [Ethos-N](https://github.com/ARM-software/ethos-n-driver-stack/blob/main/kernel-module/ethosn_driver.c) names. [Qualcomm FastRPC](https://github.com/qualcomm/fastrpc) is CPU/DSP RPC transport; its presence alone is not NPU evidence. Unverified `apusys` names are not promoted to NPUs.

Android scanning is read-only and bounded to 256 directory entries, 256 KiB of charged path/property discovery bytes, 4096 bytes per property, 64 devices, and bounded issue records. Canonical sysfs roots and targets must stay inside the configured root. Only metadata is read from the fixed device-node paths; no device is opened, no ioctl is issued, and no runtime SDK is loaded. Portable fixtures and Unix symlink fixtures cover missing interfaces, unknown transports, byte/entry limits, alias deduplication and escaping links. Running these fixtures is separate from qualifying an Android device.

The top-k literal was corrected to an exact hexadecimal f32 value and both embedded tensor shaders pass Naga validation. Later hosted runs [41273657755](https://github.com/mediaprophet/etalon/actions/runs/41273657755) and [41274003094](https://github.com/mediaprophet/etalon/actions/runs/41274003094) passed 18 cases and failed the canvas case and subsequent lease case through device loss.

The corrected source `56f8f87c` also passed the complete browser controller on Windows Chrome 156: 20 cases on Intel graphics, 20 on SwiftShader Core, 20 on SwiftShader Compatibility, and all injected adapter/property/negotiation checks. Those local device reports are not uploaded automatically.

The Linux [isolated controls](https://github.com/mediaprophet/etalon/actions/runs/41275131616) separated configuration from acquisition. Configuring an isolated rgba16float context and awaiting its error scopes succeeded, with no device loss and successful queue completion. Acquiring a presentation texture, including baseline RGBA8, lost the device independently of explicit texture destruction or cleanup order. Chromium reported an unavailable `SharedImageBackingFactory` and failure to create the shared image. Changing the software compositor/Vulkan selection did not resolve that environment limitation.

The capability query must validate configuration without allocating a presentation texture. Configuration acceptance is not a presentation test. Offscreen render/readback remains a real GPU case; Linux headless canvas presentation remains failed evidence until tested in an environment providing the necessary shared-image path. The recorded failures are not reclassified as successful GPU execution.

## API and behavior changes

- `ForwardArena::try_new_with_budget(device, max_batch, hidden_dim, num_layers, byte_budget)` checks multiplication, padded aggregate residency, `max_buffer_size`, and storage-binding limits before allocation. Three storage buffers and one staging buffer count toward the budget. The retained `new` wrapper uses a 256 MiB default and panics clearly on rejection; callers needing recoverable failures should use the fallible constructor. The new private readback state means external struct-literal construction is no longer supported.
- `try_readback_byte_size` and `try_record_readback_copy` reject invalid batch capacity, speculative batches above 16, and source/staging size violations. Existing convenience methods retain their signatures and reject invalid requests explicitly.
- `try_read_token_async` returns typed failures, including concurrent `Busy`; `read_token_async` retains an `Option` convenience result. Dropping a pending future unmaps its staging buffer. Native token mapping currently allocates callback state and starts a worker that polls with a five-second timeout. Native blocking readback now respects poll failures. On WASM, `try_read_token_blocking` returns `BlockingUnsupported` before starting a map; the older `Option` wrapper returns `None`.
- `GpuRadixSorter::sort_indices_async` and `GpuQuinSieve::sieve_eq_indices_async` write into caller-supplied slices and return `Result<usize, GpuQueryError>`. Existing native synchronous wrappers remain. Native callers must continuously progress the device from another polling owner while awaiting these async methods, or while awaiting `HalComputeLane::wait_for_async`; the browser event loop supplies this service on WebGPU.
- **Attention ABI correction:** bind `FusedAttentionParams`, the actual **96-byte** shader uniform, at binding 2. The six bindings are hidden input, weight words, uniform, KV storage, output storage, and mask words. The legacy 48-byte `AttentionParams` configuration type remains, but is not the GPU uniform ABI. Both tensor pipelines add fallible limit-checking constructors. Fused attention requires five compute storage buffers, a 64-invocation workgroup and 11,104 bytes of workgroup storage. Top-k requires three storage buffers and 8704 bytes after adding explicit candidate-index scratch.
- Top-k now excludes NaNs and invalid lanes, distinguishes valid negative-infinity candidates from exhausted entries, keeps lower-index ties, and emits `u32::MAX` for exhausted candidates. Attention avoids eager out-of-bounds accumulator reads and preserves dictionary-path selection when quantization flags are present.
- **Breaking lease API:** `SubmissionLease::new` and public resource/region/token fields are removed. Construct through `HalComputeLane::lease_submission(command_buffer, resource, region)`; inspect `region()` and `token()`; recover ownership with `try_reclaim(self, &issuing_lane)`. Queue identity, issued/completed fence state and retained ownership gate reclamation. Queue callbacks keep the resource alive when the handle is dropped early. There is no `reclaim_async` API; callers can await lane completion and then try reclamation. Native resources must satisfy the lane's thread-safety bounds.

## Qualification procedure and outstanding work

Use an ordinary secure browser context first. Record `navigator.gpu` exposure, adapter-request attempts, browser/OS versions, `chrome://gpu` diagnostics and any applicable policy/driver restrictions. Chrome blocklists and Android protection policies are external acquisition gates; the library cannot override them. Browser WebGPU delegates to the browser's GPU implementation, so a native Etalon Vulkan workaround would not change Dawn's driver behavior. This document does not prescribe disabling workgroup initialization, protection settings, validation, or driver safety gates.

The browser report must identify the exact candidate and selected feature level, execute all declared GPU cases, validate outputs and guards, and record device loss or uncaptured errors as failures. The domain cases compare actual Etalon pipeline outputs, not substitute shaders: stable radix/sieve row oracles, top-k ties/tails/NaNs/negative infinity, one-token attention `[3,-2]`, all-masked finite zeros, repeated token copies, busy/cancel/remap, and queue-retained leases. Canvas qualification exercises lazy configuration validation, preserved device/format configuration, and subsequent real GPU buffer readback. It does not acquire a presentation texture or establish presentation support.

Outstanding gates are hosted browser execution, physical Android browser execution, native Android GPU tests, Android discovery on permitted real interfaces, and any separately admitted NPU runtime/execution workload. Native crate tests, Unix-only fixtures and broader GPU regression coverage retain their own reports. No mobile speed, universal hardware support, zero-heap decode, or CTS claim follows from this candidate's source changes.
